# Задача: строгая иерархия категорий в каталоге gade.uz (после аудита)

Заказчица требует чёткую структуру **Категория → Подкатегория → 2-я подкатегория (если есть)**, максимум 3 уровня.
Аудит (Фаза 0) уже проведён — его результаты ниже, повторять его не нужно. Контекст сброшен, поэтому всё нужное
для работы собрано в этом файле.

Подтверждено по коду:
- `ensureCategory()` создаёт узел **всегда корневым** — `parentId` не передаётся никогда. Плоская модель зашита в синк.
- Поиск существующей категории идёт **только по `slug`**, без нормализации имени.
- `resolveCategoryIds()` возвращает категорию + **только прямых детей** → третий уровень выпадет из фильтрации и счётчиков.
- В `listProducts()` alias `parent_categories` поднимается ровно на один уровень → при 3 уровнях «корнем» станет подкатегория.
- Дедуп секций по `slug` в каталоге уже поправлен ранее — повторы заголовков на скриншоте были артефактом рендера.

Billz (сэмпл 20 товаров): у 19 из 20 `categories: []`, у одного — единственный узел «Ногти» с `parent_id: ""`.
Вывод: Billz отдаёт плоский одиночный тег, иерархии там нет. **Источник истины по категориям — наш сайт.**

## Что нужно перепроверить в первую очередь (пункты A–C)

### A. Синк обнуляет привязки товаров — почини это ПЕРВЫМ коммитом
В `upsertProduct()` (`src/lib/billz/sync.ts`) в объект `values` безусловно кладутся `categoryId` и `brandLineId`,
а `ensureCategory()` при пустом `p.categories` возвращает `null`. Значит каждый синк выполняет
`UPDATE products SET category_id = NULL` для всех товаров, у которых Billz не отдал категорию.
Это источник 18 бесхозных товаров и главный риск для любой ручной расстановки.

Подтверди по коду и исправь до любых миграций:
- `categoryId` и `brandLineId` записывать только при INSERT нового товара;
- при UPDATE не включать эти поля в `set`, если новое значение `null`;
- добавить в `SyncResult` счётчики `categoryKept` / `categoryAssigned` и вывести их в `sync_log`;
- показать фикс отдельным диффом.

### B. Сэмпл из 20 товаров нерепрезентативен
Если бы у 95% товаров `categories` было пустым, бесхозных было бы не 18, а почти весь каталог.
Прогони read-only скрипт по **всем** страницам Billz и посчитай: сколько товаров с непустым `categories`,
какие уникальные `name` встречаются, есть ли у них `parent_id`, сколько товаров в нашей БД имеют `category_id`
при пустом `categories` в Billz. Результат — отдельным разделом в `docs/category-audit.md`.
От этого зависит, насколько сайт остаётся единственным источником истины.

### C. Хак группировки в каталоге рисует товары под чужим заголовком
В `src/app/catalog/page.tsx` остался блок:
```ts
while (sub.length > 1 && sub[sub.length - 1].items.length < 4) {
  const tail = sub.pop()!; sub[sub.length - 1].items.push(...tail.items);
}
```
Он сливает хвостовую группу в предыдущую — товары одной подкатегории отрисовываются под заголовком другой.
Это ровно жалоба «товары не в тех подкатегориях», которой в БД не видно. Плюс группировка идёт в пределах
страницы из 48 товаров, поэтому группа, разорванная пагинацией, даёт повтор заголовка на соседних страницах.
Оба момента убрать в Фазе 5.

## Фаза 1. Инварианты в БД
Миграция через `npx drizzle-kit generate` (существующие миграции не редактировать):
- `categories`: `level` (smallint 1..3), `path` (слаг-путь `makiyazh/brovi/karandashi`, уникальный),
  `billz_category_id`, `is_locked` (ручная расстановка — синк её не перетирает);
- уникальный индекс на `(coalesce(parent_id, 0), lower(btrim(name)))`;
- CHECK `level between 1 and 3`; проверка `parent.level = level - 1` (триггер либо код + тест);
- `products.category_id` = **всегда лист**; товары, висящие на узле с детьми, переезжают в подкатегорию «Другое» своего корня;
- новая таблица `category_aliases (billz_name_normalized unique, category_id)` — чтобы разовые правки распределения
  переживали синхронизацию;
- бэкфилл `level` и `path` для существующих 27 категорий в той же миграции.

## Фаза 3. Защита синка от регрессии
- `ensureCategory()` → `ensureCategoryPath(names: string[])`: идёт по пути, на каждом уровне ищет узел по
  `(parentId, нормализованное имя)`, при отсутствии создаёт с корректными `parentId`, `level`, `path`;
- нормализация имени: trim, схлопывание пробелов, NBSP → пробел, `ё` → `е`, casefold; slug формировать из полного пути;
- товар привязывается к самому глубокому узлу пути;
- перед созданием узла проверять `category_aliases`;
- узлы с `is_locked = true` синк **не переподвешивает и не переименовывает**;
- новые неизвестные узлы Billz кладутся под служебный скрытый корень «Новые из Billz» и попадают в отчёт `sync_log`,
  а не сыпятся в витрину;
- прогнать синк на копии данных / в dry-run режиме и показать, что ни одна существующая привязка не изменилась.
